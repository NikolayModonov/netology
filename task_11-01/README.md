### Задание 1. СУБД

1.1. Реляционные СУБД (PostgreSQL, MySQL). Они обеспечивают строгую схему данных, целостность (ACID) и отлично подходят для сложных аналитических запросов и финансовой отчетности.

1.1.* Redis. Использование Redis в качестве кэша для хранения готовых хэшей или сессий значительно ускорит работу.

1.2. Для лендингов - документо-ориентированные (MongoDB), так как данные лидов могут иметь разную структуру. Для CRM - реляционные (PostgreSQL), чтобы четко связывать клиентов, сделки и менеджеров. Но если нужен максимум гибкости, то для обоих случаев подойдет MongoDB.

1.2.* Да, можно закрыть одной СУБД - PostgreSQL, используя тип данных JSONB. Это даст строгую структуру для CRM и гибкость для лендингов. Либо полностью на MongoDB.

1.3. Документо-ориентированные (MongoDB) или реляционные (SQLite/PostgreSQL). Структура документа проста и понятна, легко вносить изменения.

1.3.* Да, можно использовать PostgreSQL, создав отдельную схему или таблицы для этого отдела.

1.4. Графовые СУБД (Neo4j). Они созданы специально для работы со сложными связями и быстрым поиском маршрутов между объектами.

1.4.* Да, можно подключить отдел закупок к графовой СУБД, так как закупки - это тоже связи между поставщиками, объектами и логистикой.

1.5.* Да, можно использовать мультимодельную СУБД (ArangoDB), которая поддерживает реляционные, документные и графовые данные в одной базе.

### Задание 2. Транзакции

2.1. Шаги выполнения успешной транзакции:
* Авторизация в платежной системе и проверка баланса счета отправителя.
* Списание средств со счета отправителя (банка).
* Отправка транзакции в платежный шлюз/процессинг оператора связи.
* Проверка номера телефона и зачисление средств на баланс абонента оператором.
* Отправка подтверждения об успешном зачислении обратно в банк.
* Запись транзакции в журнал (лог) и уведомление пользователя об успехе.

2.1.* Шаги выполнения автоплатежа:
* Система по расписанию инициирует автоплатеж.
* Банк проверяет баланс.
* Автоматическое списание средств без подтверждения пользователем.
* Отправка запроса оператору связи.
* Зачисление на баланс телефона.
* Отправка пуш-уведомления или SMS об успешном автопополнении.

### Задание 3. SQL vs NoSQL

3.1. Преимущества SQL-систем по отношению к NoSQL:
* Строгая схема данных и гарантия целостности (ACID).
* Высокая надежность для сложных транзакционных систем.
* Стандартизированный язык запросов (SQL) с огромной базой знаний.
* Отличная аналитика и поддержка JOIN между таблицами.
* Меньше риск потери данных или рассинхронизации.

3.1.* Преимущества NewSQL систем:
Горизонтальное масштабирование (как в NoSQL) при сохранении строгой консистентности и ACID-транзакций (как в SQL).

### Задание 4. Кластеры

Критерий выбора: скорость записи и консистентность данных (CAP-теорема).
Лучше всего справится модель распределенных вычислений MapReduce. Она позволяет разбивать огромные задачи на 1000 машин (Map), параллельно обрабатывать данные и собирать результат воедино (Reduce), что идеально для больших объемов вычислений.
