# Домашнее задание к занятию «Микросервисы: принципы»

## Задание 1. API Gateway

Требования: маршрутизация, проверка аутентификации, терминация HTTPS.

| Решение | Маршрутизация | Аутентификация | Терминация HTTPS | Примечание |
| :--- | :--- | :--- | :--- | :--- |
| **Nginx** | По URL, хостам | Через сторонние модули (Lua) | Да | Высокая производительность, но сложно расширять под специфичный auth |
| **Kong** | По URL, методам | Встроенные плагины (JWT, OAuth2) | Да | Легко настраивается, богатая экосистема плагинов |
| **Traefik** | По правилам (headers, path) | Встроенный ForwardAuth | Да | Отлично работает в динамических средах (K8s, Docker) |
| **Yandex API Gateway** | По URL, методам | Встроенная авторизация (JWT, IAM) | Да | Полностью управляемый облачный сервис |

**Выбор: Kong.**  
Он наилучшим образом закрывает все три требования из коробки. Имеет встроенные плагины для аутентификации (без необходимости писать кастомный код на Lua), поддерживает гибкую маршрутизацию и терминацию TLS. При этом Kong можно развернуть локально в Docker, что удобно для тестирования.

## Задание 2. Брокер сообщений

Требования: кластеризация, хранение на диске, скорость, форматы, разграничение прав, простота эксплуатации.

| Брокер | Кластеризация | Хранение на диске | Скорость | Форматы | Разграничение прав (ACL) | Простота эксплуатации |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| **RabbitMQ** | Да | Да | Средняя | Множество (AMQP, MQTT, STOMP) | Гибкая (vhosts, users) | Высокая (удобный UI) |
| **Apache Kafka** | Да | Да (долгосрочное) | Очень высокая | Свой протокол, JSON, Avro | Высокая (через KIP-500) | Средняя (требует ZooKeeper/KRaft) |
| **NATS** | Да | Да (через JetStream) | Очень высокая | JSON, Protobuf | Базовая | Высокая (один бинарник) |
| **ActiveMQ** | Да | Да | Низкая/Средняя | Множество (JMS, AMQP) | Гибкая | Средняя |

**Выбор: RabbitMQ.**  
Хотя Kafka быстрее, RabbitMQ выигрывает в простоте эксплуатации (наличие удобного веб-интерфейса, легкий старт в Docker) и гибкости разграничения прав (vhosts). Он поддерживает все необходимые форматы (AMQP, MQTT) и отлично подходит для учебных и средних проектов, где не требуется обрабатывать миллионы сообщений в секунду.
