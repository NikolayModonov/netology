# Домашнее задание к занятию «Микросервисы: масштабирование»

## Задание 1. Выбор оркестратора контейнеров

Для выбора оркестратора были проанализированы три популярных решения: Kubernetes, Docker Swarm и HashiCorp Nomad.

| Критерий | Kubernetes | Docker Swarm | HashiCorp Nomad |
| :--- | :--- | :--- | :--- |
| Автоматическое масштабирование | Да (HPA) | Нет (только ручное) | Да (через Autoscaler) |
| Самовосстановление | Да | Да | Да |
| Балансировка нагрузки и Service Discovery | Да (встроенный) | Да (встроенный) | Да (через Consul) |
| Обновление без простоя (Rolling Update) | Да | Да | Да |
| Управление секретами и конфигами | Да (Secrets, ConfigMaps) | Да (Docker Secrets) | Да (Vault) |
| Логирование и мониторинг | Да (огромная экосистема) | Ограничено | Да (через интеграции) |
| Поддержка разных сред | Да (Namespaces) | Ограничено | Да |

**Обоснование выбора: Kubernetes.**
Kubernetes (K8s) выбран как наиболее подходящий инструмент, так как он закрывает все заявленные требования из коробки. В отличие от Docker Swarm, он обладает продвинутым механизмом автоматического масштабирования (Horizontal Pod Autoscaler) и встроенной поддержкой изоляции сред (Namespaces). 
Несмотря на то, что Nomad легче в установке, Kubernetes является индустриальным стандартом для микросервисной архитектуры, предоставляя самую богатую экосистему инструментов для мониторинга, логирования и управления конфигурациями.
